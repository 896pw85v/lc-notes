# 3. Longest Substring Without Repeating Characters

> Given a string s, find the length of the longest substring without duplicate characters.

This has been a nightmare to me since the first time I tried string related problems, when it was not even algorithm, just programming begginer practice. 

The most intuitive approach is to accumulate substring char by char, and each time there is a new char, iterate the substring for equal char. In worst case that `s` has no repeated char, time complexity is O($N^2$)

First try is O(N), but it's stupid.  
``` Java
import java.util.*;

class Solution {
    public int lengthOfLongestSubstring(String s) {
        HashMap<Character, Integer> start = new HashMap<>();
        HashMap<Character, Integer> end = new HashMap<>();        
        for (int i = 0; i < s.length(); i++) {
            Character c = s.charAt(i);
            if (!start.containsKey( c)) {
                // if not in start means never seen, no repeat
                start.put(c, i); 
            } else if (!end.containsKey(c)) {
                // if in start but not in end, means this is first repeat
                end.put(c, i);
            } else {
                // means this is a new repeat -> find larger gap
                int head = start.get(c);
                int tail = end.get(c);
                if (tail - head > i - tail) continue; 
                else {
                    start.put(c, tail); 
                    end.put(c, i);
                }
            }
        }
        if (end.isEmpty()) return 0; // no repeat at all
        int head = 0;
        int tail = 1; 
        // find largest gap
        for (char c : end.keySet()) {
            int h = start.get(c);
            int t= end.get(c);
            if (t - h >= head - tail) {
                head = h; 
                tail = t;
            }
        }
        return tail - head;
    }
}
```
It works by reccording the gaps between each repeated character pair, and find the largest gap. But the largest gap is not the target, e.g.: 
```
"abcdfdhijklmna"
^ here and    ^ here
```
There were some attempts to "optimize" it. I won't put them here. 

The second attempt is more thought out, using set: 
``` Java
import java.util.*;

class Solution {
    public int lengthOfLongestSubstring(String s) {
        HashSet<Character> res = new HashSet<>(); // reccords every seen char
        int l = 0; 
        int max = 0; 
        for (int i = 0; i < s.length(); i++) {
            Character c = s.charAt(i);
            if (res.contains(c)) {
                // means repeat. Dump current reccord and start new
                if (l > max) max = l; // if current length is longer
                // restart
                l = 1;
                res.clear();
            } else {
                l++;
            }
            res.add(c);
        } 
        if (l > max) return l; // in case of s doesn't end with a repeated char
        return max;
    }
}
```
This is very close to it. Set is a data structure with constant time lookup, perfectly for repetition. But the problem is, when the repeated char is in the middle of the current substring, dumping the whole substring loses a lot: 
```
"abcdefghXijklmnopqrstXuvw"
         ^------gap---^--^
 ^----current sub-----^
```
The set stores the current sub, and the gap should be continued with the rest. Dumping the current sub means new substring starts from the new 'X'. That's a problem, but set is unordered, there is no way to know which part of the set should be dumped, unless I iterate the string reversely. So I need another data structure. 
``` Java
import java.util.*;

class Solution {
    public int lengthOfLongestSubstring(String s) {
        HashMap<Character, Integer> res = new HashMap<>(); // store location
        Deque<Character> deque = new ArrayDeque<>(); // store in order
        int l = 0; // stores current length
        int max = 0;      
        for (int i = 0; i < s.length(); i++) {
            Character c = s.charAt(i);
            if (res.containsKey(c)) {
                // repeat. dump substring before the first repeated char
                if (l > max) max = l;
                l = i - res.get(c); // gap is first to new, or size of the deque (hint)
                while (!deque.peekFirst().equals(c)) {   
                    // until the head is the repeated char                 
                    res.remove(deque.poll());
                    // remove in order from deque, remove by that order from hash map
                }
                deque.poll(); // this is the repeated char
                // so now, length is reccorded, new length continues from gap
            } else {
                // never seen. This else clause is avoidable. But it's ok
                l++;
            }
            res.put(c, i);
            deque.addLast(c);
        } 
        if (l > max) return l;
        return max;
    }
}
```
This is good enough. But I can optimize. Why store indexes in hashmap when it is only used to calculate the gap length? If there is no repeated char, all those space is wasted. Besides, the deque and the hash map are themselves representations of the substring, with matching sizes. A simple optimized solution is: 
``` Java
import java.util.*;

class Solution {
    public int lengthOfLongestSubstring(String s) {
        HashSet<Character> res = new HashSet<>(); // store location
        Deque<Character> deque = new ArrayDeque<>(); // store in order
        int max = 0; 
        for (int i = 0; i < s.length(); i++) {
            Character c = s.charAt(i);
            // deque size = substring length
            if (res.contains(c)) {
                if (deque.size() > max) max = deque.size();
                while (!deque.peekFirst().equals(c)) {                    
                    res.remove(deque.poll());
                }
                deque.poll();
            } 
            res.add(c);
            deque.addLast(c);
        } 
        if (deque.size() > max) return deque.size();
        return max;
    }
}
```
This solution has $O(N)$ time complexity. The space complexity would never exceed the size of character set, typically less than 100, or the entire Unicode. 

The other solutions I saw online uses a hash map to store locations of char, and two int pointers to represent the substring. Each time there is a repeated char, the current length `right - left + 1` is compared to `max`, then left pointer jumps to the repeated char. 
```
"y z a b c d e a b c d..."
 ^ left|       ^ right
       ^ jumps here
```
Very clever. Time and space complexity is roughly the same. But it avoids using deque, which is extra space, and deque operations are linear. Also, when I gave up on hash map because it doesn't give me easy access to the `char`s in order, this solution solves by comparing `left < index`. Because when the repeated char is on the left of `left`, it's already out of the substring. 

I never thought about using two pointers.
